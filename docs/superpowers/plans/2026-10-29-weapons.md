### Technical defaults chosen by this plan (not new gameplay approvals)

1. **Catalog/lifetimes:** compiled C++ value catalog in `cpp/src/starter_content.cpp`, no runtime file parser or GDScript stat dictionary. `shared_ptr<const ItemCatalog>` retained by catalog-aware Characters; keep `Character::create(config)` and add `create(config, shared_ptr<const ItemCatalog>)`. Material records carry explicit seven-entry durability tables; composed weapon stats are explicit definition values, not an invented material scaling formula. Forward declarations avoid items/weapon_rules/character include cycles.
2. **Legacy migration:** retain placement-only `ItemRef` storage compatibility. Untagged records are not weapon/shield/armour definitions and confer no combat stats; no usable defined weapon means locked unarmed fallback. Migrate tagged combat fixtures to catalog-backed instances in Task10; do not silently synthesize stats for definition-less tagged weapons. No save/load migration is implied (none exists). If live gameplay now relies on such a record, stop to identify its intended definition rather than assign balance.
3. **IDs/validation:** nonzero uint64 domain IDs in C++; starter bridge-visible IDs ≤INT64_MAX. Reject negative/zero/unrepresentable IDs before narrowing. Per-session monotonic instance allocator reserves unique IDs before valid work starts (gaps after failure allowed); no recycling/collision/wrap. No arbitrary item/material creation binding. Finite nonnegative costs/weights/components, positive declared requirements/max durability/max reach; speed .1–2, min reach0..max, percentage points0..100. Generic zero cost is representable and spends0 successfully; no starter cost changes. Overflow/nonfinite results reject atomically, never clamp gameplay stats to new balance caps.
4. **RNG:** retain session `mt19937_64`; sort random technique candidates by ID; use unbiased bounded sampling (rejection on uint64 values, not modulo-only or implementation-dependent distribution golden values). No draw for disabled/sequence/basic fallback or rejected attempt; one bounded selection for a nonempty random candidate set (including singleton). Select technique before defense; part draw only after positive post-defense offense. Stage draws on a copied engine while validating derived results; commit engine/state only for a valid performed attempt, so numerical rejection cannot consume draws or stamina. Pure preview/snapshot never advances RNG. Seeded repeatability and next-engine-state tests pin this, without demanding frame-chunk-identical combat.
5. **Command/update ordering:** validated synchronous commands apply in call order before the next step, never retroactively; rejected commands preserve state. Accepted attack command interrupts both participants' work/queues immediately, and marks interruption irrevocably even if that attack is cancelled or its target dies before step. Direct sheet order methods must also clear their own pending/active work through the same hook; incoming interruption requires session coordination. Equip/config calls cannot undo earlier interruption or reset clocks. No new scheduling thread/event framework.
6. **Positive step:** validate entire roster/time/context before mutation; reconcile orders/interruption before any work result, advance each character's combat/stun/decay once, resolve ≤1 attack per ordered actor in roster order, reconcile deaths and interrupt work again, then settle surviving active work, start eligible queues, and regenerate living characters once using reconciled combat state. Work active at step entry gets elapsed time only if valid throughout observed boundaries; a newly arrived queued job starts at step end with elapsed0, never credits approach time. Commands are observed at simulation-step boundaries, not timestamped inside a step. A work action already settled by a completed prior step stays completed; an accepted attack at the boundary before the step that would settle work interrupts first, including the exact-completion tie. Do not infer unobserved subframe arrival/order from a large delta; test a command before the completion step, the exact tie, and a command after a previously settled completion. Retain existing no-catch-up combat. Zero step reconciles invalid orders and interrupts invalid work/queues, but advances no clocks, starts no queue, performs no hit/completion/regen.
7. **Timeline oracle:** with stun_remaining=.75, clocks attack1/defense.5/technique2, step.5 leaves stun.25 and clocks unchanged; then step.5 leaves stun0 and clocks .75/.25/1.75. Decay resumes for .25s only. Exact expiry allows an otherwise ready actor at that update's attempt phase; a fresh stun applied by an earlier roster actor lasts2 from that phase (not reduced again). Threshold changes check triggering only on the next positive-damage hit; decay uses current threshold. No time bank or retroactive extra attacks.
8. **Technique controls:** state separates `enabled`, `player_controlled`, saved sequence/index and per-ID cooldowns; no conflation of empty sequence with disabled. Skip unsupported/unlocked failures even on Wait; Wait applies only to cooldown. All-skipped basic leaves index at its starting position after one loop. Job-neutral starter definitions use the weapon's resolved job for rank1 eligibility; fixture title grants bypass rank unlock only, never weapon support/usability. Editing/toggle/controller commands don't draw RNG or clear cooldowns; only a sequence edit resets its index.
9. **Work lifecycle:** one queue OR one active job per character. Reject a second request while either exists; Cancel then reselect. Accepted bench approach replaces movement/attack like a move; combat eligibility still includes incoming pursuit. New floor/attack order clears queue; move always interrupts active even if destination remains in range. Invalid requests preserve a valid prior job. Repair/enchant targets must be owned eligible items, stored OR equipped; do not invent a backpack-only prerequisite. While active, block target equip/transfer; disappearance through removal/actor loss interrupts. Benches/items are stable IDs revalidated every step, not retained node pointers. Closing/escaping a popup only hides it; Cancel explicitly cancels. Queue is not an active transaction: no material debit, skill snapshot, item lock or XP until start.
10. **Reward/event seams:** narrow `award_work_xp(SkillJob,unsigned)` shared by Character/Skills, internally reusing progression arithmetic, used by settlement only; existing public `record_use` stays fixed1 and no arbitrary XP bridge. Independent C++ constants for craft/repair/enchant default1 and three wear costs default1. Session collects immutable per-step performed-swing events; extension drains once after each successful step for visuals. IDs and computed damage come from C++; popup opening/polling cannot replay a swing. Display positive damage with adaptive decimals/significant digits, never positive→"0"; animation timing/mesh socket offsets are presentation defaults, not combat timing.

## Exact arithmetic / action contract

Use percentage **points** in definitions/snapshots; convert once. Prefer checked double intermediates; validate float conversion before applying existing float HP APIs. Definitions reject invalid input atomically; validate a performed action's derived results before spending, RNG or mutation.

1. Resolve actual weapon job using family/matching specialization, independent handedness. Choose right usable weapon then left; deduplicate two-handed reservation. Shield never attacks. If none, use Unarmed/Boxing/Taekwondo existing rules: `(0,0,8)`, reach0–1.5, cost8, speed1, E1, quality factor1, no weapon wear/requirements/techniques. Do not invent new unarmed limb gates.
2. Requirements: sum base+enchantment requirements per attribute; check each effective attribute and resolved trained weapon rank. Each positive declared requirement gives `min(actual/required,1)^2`; E is the minimum (not product); absent requirements are omitted. Being under requirements does not forbid equip. Under-skill applies BOTH E and trained/200.
3. Basic quality scales components by `[1,2,4,8,16,32,100]`. For Blunt Edge use `base_blunt × quality + sum(fixed_added_blunt)`; then each component multiplies by `trained/200 × E × technique_factor × exhaustion × minimum_range × durability`. Basic factor1; exhausted .5 iff unpaid, minimum .5 strictly inside min, zero durability .33. Each stacks independently; positive durability1 has no penalty. Enchants remain attached and active at0. Apply target-only title modifier only to a real eligible target; no dragon tags on dummies.
4. Attack `rate=(.2+2.8×trained/200)×weapon_speed×E`; cooldown `clamp(1/rate,1/3,5)`, E0→5 without divide by0. Exhausted doubles then reclamps. Weapon speed .1..2, starters1. Attack cost `(technique override OR weapon cost) × (2−E)`. Fully afford→pay exactly once; otherwise pay NOTHING, still perform exhausted. Fractional costs work. No weight handling penalty.
5. Ready defense: usable shield first even mitigation/durability0. Otherwise compare relevant effective Blocking vs Dodging with usable weapon, ties dodge; no weapon→dodge. Shield matching spec, weapon basic Blocking, dodge chosen matching spec; clocks use trained rank, not comparison values. Shared defense clock uses `.2+2.8×trained/200` and same band; block and dodge each cost8, independently tunable. Unpaid action pays0, doubles/reclamps clock. Stun prevents defense entirely. A ready defense against zero offense is still attempted: pay its normal stamina cost if affordable, otherwise apply exhaustion, and start the defense cooldown. It prevents nothing and therefore grants no defense XP, Wall progress, block wear or body-part draw.
6. Block each incoming component before armour: mitigation fraction `base_percent/100 × (durability0 ? .33 : 1) × (unpaid ? .5 : 1)`. Dodge fraction1, or .5 unpaid. Penetration does not affect this. `prevented=sum(incoming−after_defense)`. Positive prevention gives defense XP1, plus Wall and blocking-item wear1 for block only, even if armour would absorb everything. Zero mitigation/prevention grants neither; partial defense may reward both sides.
7. If any post-defense component >0, sample one uniform part, then read only mapped piece. `R[type]=max(0,resistance[type]−penetration[type])`; `after_armour=after_defense×(1−R/100)`. During stun resistance0. Divide every remaining component by `1+.05×defender BASE Toughness`; sum, call `Character::damage(part,total)` once if positive. Penetration never affects Toughness. Selected part survives armour-zero damage; fully defended/zero offense has no part/draw.
8. Positive computed final damage against living target gives weapon XP1, lethal included; one applicable kill-title credit; no separate technique XP. Capture ranks/profile/start durability before awards. Final blunt adds stagger even if overkill but no new stun on dead target; no meter change while stunned. Threshold `10×effective Toughness`, no artificial cap; decay `.1×threshold/s`, floor0, paused during stun. Death clears meter/stun and cannot resume orders.
9. Attack wear1 per performed weapon attempt (basic/technique, blocked, armour-zero, E0), none on rejected attempt. Positive-prevention weapon block wear1 and shield block wear1 are separate tunables. Use starting durability for whole action; 1→0 penalty begins NEXT action. Whole durability clamps0..max; no deletion/armour wear.
10. Attack, shared defense and each technique cooldown are character-owned and survive equip/unequip/retarget/control switching. Freeze all three during stun, advance only unstunned remainder, once per session step. No move/attack/defense during stun; armour0; retained order resumes after expiry. No repeated meter buildup or stun refresh from hits during stun.
11. Craft cap: basic Smithing1–34→1,35–67→2,68–100→3; matching Weaponsmith1–63→4,64–127→5,128–190→6,191–200→7. Any lower unlocked tier allowed. Armoursmith crafting weapons uses frozen basic100→3. Repair adds `ceil(max × min(rank,100)/100)`, capped at max; no quality/max change. Weapon repair Smithing/Weaponsmith; starter shield repair BASIC Smithing. Full repair rejected before payment.
12. Craft/repair/enchant duration15s, only outside derived combat and within suitable bench reach1.5 inclusive. Validate everything before debit; valid start consumes materials atomically once and snapshots relevant trained job/rank. Completed benefit/XP/title atomic once; active cancellation/combat/move/range/death/item/bench loss gives no benefit/XP/refund. Queue clears for new move/attack, incoming combat, Cancel or bench loss free; arrival validation failure is free. Combat interruption wins exactly15s completion. Unique crafted output goes to backpack full durability, never auto-equipped.
